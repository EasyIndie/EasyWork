安装

引导脚本会探测 OS/架构、下载对应二进制、校验 sha256 后装入 PATH。

macOS / Linux 
curl -sL https://raw.githubusercontent.com/EasyIndie/EasyWork/main/bootstrap.sh | bash
Windows · PowerShell 
irm https://raw.githubusercontent.com/EasyIndie/EasyWork/main/bootstrap.ps1 | iex
  • 安装到 /usr/local/bin（可写时）或 ~/.local/bin，并创建 ew / easywork 两个入口。
  • 需要固定版本：EASYWORK_VERSION=0.4.3（macOS/Linux）或 $env:EASYWORK_VERSION='0.4.3'（Windows）。
  • 校验失败会直接中止，不会覆盖已安装的二进制。

三步开始

重复执行是安全的：已经正确的部分不会被重写。

终端 
# 1. 轻量初始化：shell 别名 + git 别名，零交互
ew init

# 2. 按 config.toml 装好全套（--dry-run 可先预览）
ew install --yes

# 3. 看状态 / 诊断
ew status
ew doctor

为什么是 EasyWork

为「人」和「AI agent」两类使用者设计：结果可预测，状态可查询。

  • 单二进制，零依赖

    发布物是静态编译的 Go 二进制，终端用户不需要 curl 之外任何运行时；下载即可用，卸载即删除。

  • 声明式配置

    一份 config.toml 描述目标环境，交互只是生成配置的前端。改配置、再 apply 即可收敛。

  • 幂等且可回滚

    只在自己的 managed section 内改写目标文件，保留你原有内容；首次接管前自动备份，卸载时还原。

  • 人类与机器都友好

    默认输出可读摘要，--json 给出字节级稳定的信封；日志一律走 stderr，方便管道与自动化。

  • 可选模块，按需安装

    核心只有 shell / git / gh / vim / ai；gh 之外的清理、运行时、Markdown、终端等按需显式指名安装。

  • 设备防休眠

    ew keepawake 用系统电源断言保护长跑任务，不需要 sudo、不改系统电源策略，状态五态可查。

新能力

长跑任务不被打断

ew keepawake 只注册系统的电源断言：macOS 用 caffeinate -s、Linux 用 systemd-inhibit、Windows 用 SetThreadExecutionState。 默认模式下「接电不睡、拔电照常节能」，屏幕仍按你的设置熄灭。

  • 不用 sudo，不改 pmset / powercfg
  • status 报告真实断言状态，而不是「进程还活着」
  • --persist 写入 LaunchAgent / systemd 单元 / 计划任务，重启自动恢复

合盖仍会睡眠——这是硬件行为，任何工具都拦不住。

开启并设为开机自启 
ew keepawake on --persist
ew keepawake status
# 期望  开启 mode=ac persist=on
# 实际  active (pid 75111, backend=caffeinate)

# 关掉并拆除自启
ew keepawake off

命令一览

无参数执行 ew 等于 ew status。

命令说明
ew init轻量初始化：shell 别名 + git 别名，零交互
ew install [组件...]安装全部或指定组件；module/component 可选子项
ew uninstall [组件]卸载并还原备份，不指定则卸载全部
ew status配置与各模块状态
ew doctor依赖 / 网络 / 控制台编码 / 电源策略诊断
ew list列出可用组件（含可选模块）
ew config get|set|edit读写 config.toml
ew keepawake on|off|status设备防休眠
ew update自升级（sha256 校验）
ew completion安装 / 移除 / 查看 shell 补全

可验证，不靠信任

  • 完整性校验

    发布附带 checksums.txt；ew update 与引导脚本都会校验 sha256，不匹配即中止。

  • 构建来源证明

    发布资产带 build provenance attestation，可用 gh attestation verify 校验来源。

  • 三平台 CI

    每次提交跑 macOS / Linux / Windows 单测与黑盒 conformance，以及 6 个目标交叉编译。

  • 数据格式稳定

    config.toml、manifest 与 managed section 标记跨版本不变，升降级无需迁移。
